# Data Model

This document is normative. Hermes must not invent fields or relationship behaviour that conflicts with it.

## Common fields

Unless marked immutable or embedded, all persisted entities have:

| Field | Type | Rule |
|---|---|---|
| id | UUID | Primary key; generated by application |
| createdAt | UTC datetime | Immutable |
| updatedAt | UTC datetime | Updated on mutation |
| archivedAt | UTC datetime or null | Used where archival is supported |

All timestamps are stored in UTC and displayed in the configured owner timezone.

- Archiving a project does not delete child records.
- Permanent project deletion is not exposed in the MVP UI.
- Restoring a project returns it to its previous non-archived status stored in `preArchiveStatus`.

### RiskRecord

Includes `projectId`, title, description, impact, likelihood, status, mitigation, ownerAgentId, targetDate, and reviewDate.

### VersionRecord

Includes projectId, versionLabel, versionType (`OFFICIAL`, `DEVELOPMENT`, `TEST`, `RELEASED`), sourceReference, changeSummary, status, createdBy, approvedAt, and releasedAt.

### Agent

Includes name, kind (`HUMAN`, `AI`), provider, model, capabilities JSON, autonomyLevel (`MANUAL`, `SUPERVISED`, `BOUNDED_AUTONOMY`), and status (`IDLE`, `ACTIVE`, `BLOCKED`, `OFFLINE`).

### ActivityRecord

Append-only record with actor, action, entityType, entityId, projectId optional, summary, metadata JSON, and UTC timestamp.

## Audit requirements

Record at minimum:

- project creation, archive, restore, and status changes;
- deliverable status and hierarchy changes;
- work-packet submission and version creation;
- reviews and decisions;
- direction requests and owner responses;
- imports, exports, backups, migrations, releases, and agent executions.

## Progress calculation

Project progress is the weighted completion of non-archived deliverables:

- `PLANNED`, `READY`, `BLOCKED` = 0%
- `IN_PROGRESS` = 40%
- `IN_REVIEW` = 80%
- `APPROVED`, `RELEASED` = 100%

Use deliverable `weight`. If no active deliverables exist, progress is 0%.

## Health calculation

Evaluate in order:

1. `BLOCKED` when an open critical blocker exists or a critical deliverable is blocked.
2. `AT_RISK` when an open high/critical risk exists or a critical deliverable is overdue.
3. `ATTENTION` when any non-critical deliverable is overdue or a revision request is unresolved.
4. `HEALTHY` otherwise.


## Product-development alignment entities

### ProjectIntent

One active intent record per project version. Fields: `projectId`, `problem`, `audience`, `desiredOutcome`, `constraints`, `nonGoals`, `successMeasures` JSON, `ownerPriorities` JSON, `commercialTarget`, `status` (`DRAFT`, `APPROVED`, `SUPERSEDED`), `approvedAt`. Approved intent is versioned rather than overwritten.

### BenchmarkBrief

Fields: `projectId`, `purpose`, `references` JSON, `dimensions` JSON, `marketBaseline`, `targetSummary`, `differentiators` JSON, `intentionalOmissions` JSON, `evidenceDate`, `status` (`DRAFT`, `APPROVED`, `NEEDS_REFRESH`). References must not be treated as permission to copy protected content or implementation.

### QualityProfile

Fields: `projectId`, `name`, `dimensions` JSON, `mandatoryDimensions` JSON, `targetLevels` JSON using `BASIC`, `COMPETITIVE`, `COMMERCIAL`, `COMMERCIAL_PLUS`, `DIFFERENTIATOR`, `status` (`DRAFT`, `APPROVED`, `SUPERSEDED`).

### QualityGateResult

Fields: `projectId`, `level` (`WORK_PACKET`, `DELIVERABLE`, `STAGE`, `RELEASE`), relevant entity ID, `outcome` (`PASS`, `PASS_WITH_ACCEPTED_RISK`, `REVISION_REQUIRED`, `BLOCKED`), `criterionResults` JSON, `evidenceIds` JSON, `riskDecisionId` optional, `evaluatedBy`, `evaluatedAt`. Gate results are append-only.

### LearningRecord

Fields: `projectId`, `sourceType` (`BUG`, `FEEDBACK`, `TEST_FAILURE`, `BENCHMARK_GAP`, `USABILITY`, `COMMERCIAL_INSIGHT`, `AGENT_FAILURE`, `RETROSPECTIVE`), `summary`, `evidenceIds` JSON, `impact`, `status` (`NEW`, `ASSESSED`, `CONVERTED`, `DISMISSED`), `convertedReference` optional. Conversion creates a normal change/backlog/requirement record; it does not silently change approved scope.

### AttentionEvent

Append-only diagnostic event: `projectId`, `type` (`OWNER_DECISION`, `OWNER_REVIEW`, `OWNER_CORRECTION`, `UNNECESSARY_ESCALATION`), `startedAt`, `endedAt`, `durationSeconds`, `relatedEntityId`, `notes`. Used only for attention metrics, never as a reason to suppress necessary escalation.

## Autonomy metrics

For a selected period:

- `autonomyRate = agent work packets completed without owner intervention / all agent work packets completed`.
- `ownerAttentionTime = sum(AttentionEvent.durationSeconds)`.
- `firstPassAcceptanceRate = work packets approved on first submitted version / reviewed work packets`.
- `autonomousRecoveryRate = recoverable execution incidents resolved without owner direction / recoverable execution incidents`.
- `escalationQualityRate = owner-required escalations judged necessary / all owner escalations`, where unnecessary escalations are explicitly classified rather than inferred.

Metrics are diagnostic and must not change safety/quality rules.
