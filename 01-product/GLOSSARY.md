# Glossary

| Term | Definition |
|---|---|
| Project | A managed initiative created from a project template or custom configuration. |
| Lifecycle stage | A domain stage inside a project, such as Discovery or Editing. |
| Build phase | A controlled implementation phase used to build VSO itself. |
| Deliverable | A required output with status, ownership, criteria, and versions. |
| Work packet | The smallest independently executable unit of work. |
| Acceptance criterion | A testable condition that must be satisfied. |
| Evidence | A file, link, note, test result, or artifact proving completion. |
| Review | A formal evaluation of submitted work. |
| Decision record | An immutable record of a consequential choice. |
| Project version | An understandable product-facing representation of an official, development, test, or released state. |
| Branch | A separate Git line of development. |
| Worktree | A physical folder containing one checked-out Git branch. |
| Agent | A human or AI executor with stated capabilities and autonomy level. |
| Environment | An isolated runtime with its own port, data, files, cache, and logs. |
